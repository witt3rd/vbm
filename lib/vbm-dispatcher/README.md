# vbm-dispatcher

**A work dispatcher as pure Lean.** A host decides whether it has headroom, chooses the next item from a leased queue (aging, dependencies, serialisation keys, class gates, deferral to hosts that are better placed), claims it, and supervises it while a worker runs: the lease is renewed at every beat, the item is finished once with the worker's typed outcome, a lost lease stops the worker and reports nothing, and cleanup happens exactly once. Proved in Lean 4; no input or output, no clock, no network.

> **Status: pre-release.** The specification and its first proofs. Nothing is published to a package registry.

## What it is, and what it is not

A specification, its proofs, a reference model (the machine driven under the port discipline) and conformance vectors (`vectors/`, format in `docs/vectors.md`): language-neutral scenarios that any interpreter runs in its own tests. `step : Config → State → Event → State × List Action` is total and pure: it has no input or output, no clock, no model and no storage. An interpreter turns each action into a call of a port (the workspace, the agent, the lander, the reviewers, the judge) and each answer into the next event. It depends on [vbm-work](../vbm-work) for the words it shares (the task, the typed outcome, the review verdict) and on nothing else.

## Build and test

Prerequisites: `git`, [mise](https://mise.jdx.dev). `mise exec -- scripts/tier1.sh` is the gate (Lean 4.35.0, pinned in `mise.toml`). The claims and the theorems that prove them are in `docs/proof-ledger.md`, generated by the gate.

## How it is built

Agents write it under mechanical gates instead of line-by-line review, to the [VBM standard](https://github.com/witt3rd/vbm). It lands directly on `main` with `.land/land-direct`, a pinned copy of [vbm-land](https://github.com/witt3rd/vbm-land).
