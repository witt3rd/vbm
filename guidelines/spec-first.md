# Specification first, in order

A change that adds behaviour lands as a specification first: types, theorems, test vectors, no placeholder proofs, no new axiom. An implementation change may then add only boundary code or code derived from the specification.
Executable domain logic that is not in the specification fails the gate. The first thing an agent produces for a feature is the specification change; the brief for any agent in this practice states the rules above.
Ratchet the numbers: the specified share may not fall, the unverified set may only shrink. Raising a baseline needs a written reason, a target and the owner's approval; a baseline never starts as "the current value is normal", it starts as a dated burn-down plan.
